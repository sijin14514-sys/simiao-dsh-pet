# 00 · 实现原理总览

一句话：**用 AI 图生视频造出 25 段透明背景的动画，交给两个桌宠运行时播放，再用一个零依赖桥接插件把 DSH
的 agent 状态实时喂给它**——期间不写一行渲染代码，所有"动作"都是真实视频。

本文按"素材 → 播放 → 联动 → 说话"四层拆解，最后列出参数表和踩坑对照。

---

## 一、总体架构

```
             ┌──────────────── 素材生产线（离线，一次性）────────────────┐
 立绘 PNG ──▶ 即梦图生视频 ──▶ 绿幕 mp4 ──▶ 抽帧/HSV 抠绿 ──▶ 归一化 ──▶ VP9-alpha webm
             └──────────────────────────────────────────────────────────┘
                                              │ 25 段 webm（640×360 / 24fps / 透明）
                     ┌────────────────────────┴────────────────────────┐
                     ▼                                                 ▼
        【形态 A】DSH 内插件 dsh-pet                      【形态 B】独立桌面程序
        Electron + React，跑在 DSH 页面里                  dsh-pet-indesktop（Python + PySide6）
        配置：pet/<前缀>-config.json                       配置：<用户目录>/config.json
                     ▲                                                 ▲
                     │                                                 │ agent_link.dsh = true
                     │                                    ┌────────────┴────────────┐
                     │                                    │ 桥接插件 @dsh-pet/bridge │
                     └────────── DSH 会话事件 ◀───────────┤ 订阅 → 写 jsonl（零依赖） │
                                                          └─────────────────────────┘
```

两条形态**共用同一套素材**，因为素材规范是同一份（见第四节）。区别只在"谁来解码播放、谁来决定下一段播什么"。

## 二、素材层：把 AI 视频变成桌宠素材

这一步是全项目最花时间的部分，也是唯一"不可替代"的部分——**动作不是代码算出来的，是视频**。

### 1. 半身像 → 全身立绘

用 AI 图片生成，参考图给原始半身像，要求产出：全身 Q 版、纯绿幕背景、脚踩地面、正面站立。
这张立绘后面会作为**每一段视频的首帧**，所以它决定了所有动作的角色一致性。

### 2. 立绘 → 绿幕视频（图生视频）

即梦 Seedance，首帧挂立绘 + 提示词。提示词必须写死三类约束（每条都对应一次真实翻车）：

| 约束 | 防什么 |
|---|---|
| **角色锁定** | 生成成别的角色（黑发猫娘）——把发色/发型/配饰/瞳色/服装逐项写死 |
| **构图强制** | 人物画太大、腿被裁出画外——写"头顶距顶边 15%~20%、脚底在画幅 85%、总高不超 60%" |
| **发型严格一致** | 头顶凭空多一根呆毛——写"不得出现首帧没有的发丝" |

另外统一要求：镜头固定、人物不位移、纯绿幕、无阴影水印、**最后一帧回到与首帧一致的正面站立**
（保证动作之间能无缝衔接）。

### 3. 绿幕视频 → 透明动画（关键的三个技术点）

```
mp4 ──ffmpeg 抽帧──▶ PNG 序列 ──逐像素 HSV 抠绿──▶ 透明 PNG ──归一化──▶ 640×360 合成 ──ffmpeg 编码──▶ webm
```

| 技术点 | 做法 | 为什么这样做 |
|---|---|---|
| **抠绿** | 在 HSV 空间按**色相**判定（70~170 且饱和度/明度达标），不是 RGB 距离 | RGB 距离会把蓝、白一起抠掉；色相判定只吃绿色 |
| **水印** | 左上 20%×12% 区域 alpha 直接置 0 | 那片是纯绿底，矩形清除零风险 |
| **归一化** | 取首尾帧的角色包围盒，站立高度统一 **267px**、脚底压在 **y=330**、水平居中 | 不归一化的话每段人物大小/位置不同，切换时会"跳" |
| **编码** | `libvpx-vp9` + `yuva420p` + **`-auto-alt-ref 0`** | 开了 alt-ref，alpha 层根本不写进 webm |

### 4. 自动化（可选）

即梦是网页应用，所以用 **Playwright** 驱动本机 Chrome，并开一个本地控制口 `127.0.0.1:7799/cmd`
（`goto / eval / click / upload / screenshot`），把"挂首帧 → 写提示词 → 提交 → 等结果 → 下载"脚本化。
每段下载后跑四道质检：绿幕、构图（底边距 ≥8px）、SHA256 查重、alpha 存在。

## 三、播放层：动画怎么"活"起来

### 形态 A：DSH 内插件（`dsh-pet`，Electron + React）

配置文件 `pet/<前缀>-config.json` 决定"有哪些动画、权重多少"：

```jsonc
"animations": {
  "idle":   ["待机呼吸"],
  "clicks": ["点击回应-开心跃动", "被吓一跳", "生气跺脚", "鼓掌庆祝", "鞠躬"],  // 点击随机抽 1
  "drag":   ["被鼠标拖拽悬空反抗"],
  "categories": [
    { "id": "小动作",   "weight": 12, "actions": [...] },
    { "id": "待机小动作", "weight": 10, "actions": [...] },
    { "id": "吃喝",     "weight": 8,  "actions": ["吃零食"] }
  ]
},
"animationWeights": { "idle": 65, "move": 5 }
```

**每段播完按权重掷骰决定下一段**，所有顶层权重 + 分类权重合计 100。这套配置就是肆喵的"性格"：

| 权重 | 内容 | 意图 |
|---|---|---|
| **65%** | 只有「待机呼吸」 | **待机池只放站着不动的**——这是"不显得一直忙着"的最有效一招 |
| 12% | 环顾/挥手/转圈 | 偶尔主动一下 |
| 10% | 打瞌睡/看书/戴耳机 | 安静地陪着 |
| 8% / 5% | 吃零食 / 走路 | 生活感 |

点击反应是 `clicks` 数组**每次随机抽 1**，所以多放几段天然就是"点击反馈多样化"。

### 形态 B：独立桌面程序（`dsh-pet-indesktop`，Python + PySide6）

不跑在 DSH 里，是**独立的 Qt 进程**：读外部角色目录
`characters/<id>/videos/{idle,turn,move,click,drag,random,events/balance}/*.webm` + `manifest.json`
（里面的 `body_box` 是可点击包围盒，实测为 `[210,58,429,336]`）。

好处是**零改代码搬运**：同一套 640×360 / 24fps / VP9-alpha / 脚底 y=330 的 webm，按目录约定放好就能用，
并且支持热加载（换角色不用重启）。

## 四、联动层：让她知道 Agent 在干什么

这是"桌宠"和"看视频的猫"的分界线。链路是三段：

```
DSH agent 生命周期事件 ──订阅──▶ @dsh-pet/bridge ──追加写──▶ dsh-<pid>.jsonl ──tail──▶ 桌宠状态机
```

### 桥接插件（`@dsh-pet/bridge`，Cordis 插件，1795 行）

| 设计点 | 做法 | 原因 |
|---|---|---|
| **零运行时依赖** | 只用 `node:fs / os / path / crypto`，`package.json` 无任何依赖 | profile 用 `file:` 链接安装时 pnpm **不装**被链接包的依赖，缺一个就让**所有 DSH profile 起不来**（2026-09 真实事故） |
| **不声明 peer** | 无 `peerDependencies` | DSH 0.2.x 有版本门禁，声明 `^0.1.x` 会被直接拒装 |
| **多实例分区** | 文件名 `dsh-<pid>.jsonl` | 多开 DSH 不互相覆盖；消费端按 mtime 取最新 |
| **防无限增长** | 单文件 >1MB 轮转成 `.jsonl.1` | 桌宠按字节偏移 tail，轮转后从头读 |
| **状态去重** | 重复 `idle` 不落盘 | 实测 `idle→working` 只隔 4ms，抖动会吃掉真实的 `working` |
| **多 agent 聚合** | 按 agent 分别记状态，**任一在忙即忙** | 全局单值会让先干完的子代理把还在干活的顶成 idle |
| **静态禁令** | 源码禁止 `require` / 动态 `import` | 惰性加载能绕过清单与门禁检查 |

事件行是扁平 JSON：`{ts, event, state?, tool?, step, sessionId, ...}`，覆盖
`AgentStatus / tool/call / tool/result / assistant/message / step/start / step/end / turn/start / turn/end /
question/requested / agent/request-error / bridge/diagnostic`。

### 桌宠侧：状态机 + 动作选择

独立程序侧读 `config.json` 的 `agent_link.dsh = true` 后开始 tail，把事件翻译成自己的状态
（日志里记作 `[DSH STATE] working -> thinking`）。**动作是按文件名关键字挑的**：

```
_LINK_MAIN_KEYWORDS  = ("代码","工作","写","打字","敲")   → 命中则挑「工作状态-*」类动画
_LINK_BREAK_KEYWORDS = ("记录","踏步","伸懒腰")            → 命中则挑「伸懒腰-*」类
兜底 = random 全池随机
```

所以 25 段素材里那 5 段「工作状态-看代码 / 戴耳机专注 / 忙碌擦汗」「伸懒腰-打盹 / 摸鱼吃零食」
就是**专门为联动做的**——文件名即路由。

### 节奏控制：三重节流

干活汇报不能刷屏，上游设计了三层：

| 层 | 间隔 | 作用 |
|---|---|---|
| 同一 Agent | 10 秒 | 防止单会话连播 |
| 全局 | 8 秒 | 防止多 agent 叠加 |
| 同一文案（同工具） | 60 秒 | 防止"跑命令"刷屏 |

气泡显示 **2600ms**；`report_gates.activity` 控制过程汇报的放行概率（默认 0.6，本项目设 1.0 不抽稀）。

## 五、说话层：台词系统

`config.json` 里三组开关：

| 键 | 作用 |
|---|---|
| `dialogue_mode: "custom"` | 用自定义台词表而不是内置文案 |
| `dialogue_phrases.global` | **30 个事件 / 88 条**文案，按事件分类（开始/思考/读/搜/改/跑/完成/报错/审批/提问…） |
| `self_talk_enabled` + `self_talk_texts` | 空闲时每 8~18 秒自言自语一句 |
| `self_talk_image_dir: ""` | **空字符串 = 纯文字气泡**（不要头像） |

台词里支持占位符 `{name}`（agent 名）、`{label}`（工具/文件名）、`{step}`（第几步），
字符串由 `persona_template.PARAMETERS` 校验，**每个事件 ≤8 行、每行 ≤240 字符**。

## 六、参数速查表

| 项目 | 值 |

| 状态集合 | working / thinking / success / error / waiting_question / idle / offline |

## 七、踩过的坑 → 对应的设计决策

| 事故 | 根因 | 现在怎么防 |
|---|---|---|
| 4 段动画**没有腿** | 源视频里人物画太大，腿的像素根本不存在 | 提示词加【构图强制】+ 下载后按行扫描"底边距 ≥8px"质检 |
| 待机动作**多一根呆毛** | 早期提示词写了"额前一缕呆毛" | 改成"卷发" + 【发型严格一致】+ 站立帧顶行像素比对 |
| alpha 丢了 | 编码漏了 `-auto-alt-ref 0`；或校验时没把 `-c:v libvpx-vp9` 放 `-i` 前 | 写进规范文档 + `检查alpha.mjs` 自动化 |
| 配置改了**不生效** | `config.json` 写成 **UTF-8 BOM**，应用解析失败静默退回内置角色 | 所有脚本写文件一律**无 BOM** |
| DSH 插件装上**装不上/起不来** | 声明了 peer（被版本门禁拒）/ 声明了依赖（file: 链接不装依赖） | 桥接强制零依赖零 peer，并写成 `verify_import.mjs` 测试 |
| 搬素材要改代码 | 两个运行时的素材规范不同 | 选型时就确认两者规范一致（同画布/同编码/同脚底线），实现零改代码 |

## 八、成果

- **素材**：25 段 AI 图生视频动画（全部透明背景、统一画布与脚底线）
- **两种运行形态**：DSH 内插件（≤0.1.x）+ 独立桌面程序（不依赖 DSH，任意版本）
- **联动**：DSH agent 状态 → 桌宠动作 + 气泡，DSH 0.1.5-rc.2 与 0.2.0-rc.2 实测均正常
- **说话**：30 事件 / 88 条自定义台词 + 8 条自言自语，纯文字气泡
- **工程化**：一键安装（.cmd / .ps1 / .sh）、自检脚本、验收清单、完整方法论文档
- **已发布**：[simiao-dsh-pet](https://github.com/sijin14514-sys/simiao-dsh-pet)（v1.4.0）
