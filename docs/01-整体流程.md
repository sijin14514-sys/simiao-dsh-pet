# 01 · 整体流程

从**一张半身立绘**到**一只会动的桌宠**，一共四步。本文给出每一步的输入、输出、工具与耗时参考；
细节点在各专题文档里。

```
 半身证件照 ──① 图片生成──▶ 全身 Q 版绿幕立绘 ──② 图生视频──▶ 每个动作一段绿幕 mp4
                                                                      │
   装进 DSH ◀──④ pet pack── 640×360 VP9-alpha webm ◀──③ 抠像/归一化/转码──┘
```

## ① 半身像 → 全身立绘（一次性）

- **为什么必须换全身**：桌宠素材要求"脚踩地面线、全身入画"，半身像拿去生成视频，模型会自由补下半身，
  而且每段补得都不一样。
- **怎么做**：AI 图片生成，**参考图 = 你的半身立绘**，提示词交代清楚：
  角色特征（发型 / 配饰 / 服装 / 瞳色…）+ 姿态构图（正面站立、双臂下垂、头顶 ~20%、脚底 ~85%、水平居中）
  + 背景（纯绿幕 #00FF00、无阴影无水印）。
- **产出**：一张 16:9、纯绿底、全身入画的立绘。它同时是后续所有视频的**首帧**。
- 本仓库的成品：`assets/肆喵-全身立绘.png`（生成提示词见 `tools/` 里的立绘脚本注释）。

## ② 每个动作 → 一段绿幕视频（最费时也最贵的一步）

- **工具**：图生视频（本文用即梦 Seedance 2.0 mini，5s / 720P / 16:9）。
- **输入**：首帧立绘 + 动作提示词（模板见 `docs/03`）。
- **产出**：每个动作一段 5 秒绿幕 mp4。
- **规模建议**：先做 **6~10 段**（待机、点击回应、两个小动作、拖拽、走路、余额）就能"活"起来；
  本仓库最终做了 20 段。**不要一次做完 100 段**——抽卡式生成会有废片，先跑通链路再上量。
- 自动化：`docs/02` 讲了怎么用 Playwright 把"上传首帧 → 粘提示词 → 生成 → 取回 mp4"脚本化。

## ③ 绿幕视频 → 桌宠素材

```sh
node tools/视频转桌宠.mjs <绿幕mp4> <动作名>     # 抽帧 → HSV 抠绿 → 归一化 → 640×360 帧
powershell -File tools/编码.ps1                  # 帧 → VP9-alpha webm
powershell -File tools/校验.ps1                  # ffprobe + 抽帧总览（人工确认）
```

三个关键点（都踩过坑）：

1. **抠像用 HSV 色相判定**（绿色色相 70~170 + 饱和度/明度阈值），不要用"离绿色多远"的 RGB/YUV 距离——
   后者会把蓝、白等颜色误抠。
2. **归一化按"站立高度"定标**：取首尾帧的角色包围盒，把站立高度统一到画布上 267px、脚底压在 y=330，
   这样 20 段动作的人物大小、落地位置才一致。
3. **编码必须 `-auto-alt-ref 0`**；**抽帧校验必须 `-c:v libvpx-vp9`**（放在 `-i` 之前），
   否则 VP9 的 alpha 层会被静默丢掉。

## ④ 做成 pet pack（不改插件）

dsh-pet 支持**文件宠物**：把配置与素材放进用户数据目录即可，无需改源码、无需重新构建。

```
$DSH_HOME/dsh-pet/pet/
├─ simiao-config.json          ← 宠物配置（动画池 + 权重 + 实例）
└─ simiao-animation/           ← 素材目录，名字必须与配置前缀一致（simiao）
   └─ *.webm
```

刷新页面即生效（桌面模式由 Helper 同步）。配置写法与"节奏设计"见 `docs/04`。

## 时间与成本参考（本文实测）

| 环节 | 单次耗时 | 备注 |
|---|---|---|
| 全身立绘（图片生成） | 1~2 分钟 | 便宜，可多抽几张挑 |
| 一段 5s 视频 | 2~5 分钟 | 含排队；额度按平台计费 |
| 一段素材转码 | 约 1 分钟 | 抽帧 + 抠像 + 编码，纯本地 |
| 20 段全流程 | 约半天（含排队与挑片） | 其中大量时间在"等生成"和"挑废片" |
