# 03 · 素材规范与验收清单

本文是"素材能进插件、看起来不崩"的硬性规范，以及我们实际翻车后总结的验收项。
**每条都对应一个真实事故**，照着做可以少走几小时弯路。

## 一、播放素材规范（dsh-pet）

| 项目 | 值 |
|---|---|
| 画布 | **640×360**（16:9）；人物脚底对齐 **y=330**（地面线），水平居中 |
| 编码 | **VP9 + alpha（yuva420p）**，webm 容器，24fps |
| 编码参数 | `-c:v libvpx-vp9 -pix_fmt yuva420p -crf 40 -b:v 0 -auto-alt-ref 0 -deadline good -cpu-used 4` |
| 时长 | 每段 3~10 秒（本文多为 5 秒） |
| 目录 | 主宠物用户素材放 `$DSH_HOME/dsh-pet/main-animation/webm/`；pet pack 放 `pet/<前缀>-animation/` |

**`-auto-alt-ref 0` 不能省**：开了 alt-ref，alpha 通道不会写进 webm。

**抽帧验证 alpha 时必须 `-c:v libvpx-vp9` 放在 `-i` 之前**：原生 VP9 解码器不还原 alpha 层，
你会以为"alpha 丢了"，其实是解码方式不对。

## 二、提示词的三个强制约束（文字锁死，别只靠首帧）

只给首帧、提示词只说"Q版猫耳女仆做个动作"，模型会**自由发挥**。我们实测到的三种翻车，分别对应三条约束：

| 约束 | 防的事故 | 模板 |
|---|---|---|
| **角色锁定** | 生成出**完全不同的角色**（黑发猫娘） | 把发色/发型/配饰/瞳色/服装逐项写出来，并写"严禁改变、严禁换成其他角色" |
| **构图强制** | 人物被画得太大，**腿被裁出画外**（4 段中招） | "全身完整入画：头顶距顶边 15%~20%、脚底在画幅 85% 处、总高不超过画幅 60%、水平居中；严禁裁掉任何身体部位" |
| **发型严格一致** | 头顶**多出一根呆毛**之类的小差异 | "头顶不得出现首帧中没有的呆毛/直立发丝；头饰覆盖处必须平整" |

另外统一加：镜头完全固定、人物不位移不出画、背景纯绿幕 #00FF00 不变、无阴影无水印、
**最后一帧回到与首帧完全一致的正面站立**（保证动作链首尾吻合）。

## 三、验收清单（每条素材入库前都过）

| # | 检查 | 判据 | 工具 |
|---|---|---|---|
| 1 | 首帧真的挂上了 | 存在 720px 宽的 `blob:` 预览图 | `tools/即梦-26-批量生成v2.mjs` |
| 2 | 背景是纯绿幕 | 抽一帧采样四角（跳过左上水印区），≥3 角为纯绿 | `tools/即梦-41-下载新结果.mjs` |
| 3 | **角色没被裁出画外** | 抽帧后按行统计非绿像素，角色内容**底边距画幅底 ≥8px** | 同上 |
| 4 | 不是旧文件 | 与已入库素材 **SHA256 查重** | 同上 |
| 5 | alpha 真的在 | libvpx 解码抽帧，透明像素占比显著 >0 | `tools/检查alpha.mjs` |
| 6 | 画布/尺寸对齐 | 全部 640×360、脚底线一致 | `tools/校验.ps1` |
| 7 | 动作幅度够 | 逐帧扫描内容行范围（太小 = 看不见在动） | `tools/校验.ps1` / 肉眼看总览图 |
| 8 | 肉眼确认 | 拼一张"每段一帧"的总览图看一遍 | `tools/校验.ps1` + `tools/校验.mjs` |

> 第 3 条是**最容易被忽略**的：视频本身没错，是源视频里人物就被画到了画面外，腿的像素根本不存在，
> 后期救不回来。发现后只能重做——而重做时把"构图强制"写进提示词就基本不再出现。

## 四、水印

生成平台会在画面左上角打半透明水印。因为那片区域是纯绿背景，**抠绿后按矩形直接清掉**即可
（`tools/视频转桌宠.mjs` 里已内置：左上 20%×12% 区域 alpha 置 0）。

## 五、自检小抄

```sh
node tools/检查alpha.mjs 输出.png          # 透明像素占比
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height -of csv=p=0 x.webm
```
